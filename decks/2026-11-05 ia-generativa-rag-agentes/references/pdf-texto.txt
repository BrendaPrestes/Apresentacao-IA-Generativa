Qual a diferença entre Transformers e LLMs? 
-> Transformers é uma arquitetura de rede neural.  É uma rede neural 
artificial é um modelo de IA inspirado, de forma simplificada, no 
funcionamento dos neurônios do cérebro humano. Ela aprende 
analisando muitos exemplos e encontrando padrões. Ele é o "motor" que 
permite que a IA compreenda e gere linguagem de forma eficiente. 
Modelos como GPT3, GPT4,  BERT e outros são baseados na arquitetura 
Transformer  
->Modelos como RNNs e LSTMs tinham dificuldade em manter e utilizar 
informações de partes anteriores de uma sequência, especialmente se a 
sequência fosse longa. Os Transformers, com seu mecanismo de atenção, 
podem associar palavras distantes de forma eficiente, permitindo que eles 
capturem contexto e dependências de longo alcance.  
=====PAGE=====
-> Ao contrário das RNNs, que processam sequências de forma serial, os 
Transformers podem processar todos os tokens de uma sequência 
simultaneamente. Isso não apenas acelera o treinamento, mas também 
melhora a capacidade do modelo de aprender padrões complexos.  
-> Enquanto modelos como Word2Vec e GloVe geram um único 
embedding (vetor) para cada palavra, independentemente do contexto, os 
Transformers produzem embeddings contextualizados. Isso significa que a 
representação vetorial de uma palavra pode variar dependendo do seu 
contexto na frase, permitindo nuances semânticas mais ricas.  
 
-> Hugging Face é uma plataforma onde desenvolvedores podem 
encontrar, compartilhar e usar modelos de Inteligência Artificial, 
principalmente LLMs (Large Language Models). Ou seja, a "loja" mundial 
onde todo mundo baixa modelos de IA pré-treinados.

05: FiNE - TUNING: 
Fine-Tuning (Ajuste Fino): Você pega esse modelo pronto e "inteligente" e 
treina ele um pouquinho mais, usando apenas um conjunto pequeno de 
dados da sua área específica   
É um processo de ajuste fino ou refinamento de um modelo pré-treinado. 
Esse processo envolve a reconfiguração do modelo para que ele se adapte 
melhor a uma tarefa específica ou conjunto de dados. 

=====PAGE=====
-Economia de tempo e dinheiro; ensina um estilo, padrão ou tarefa 
específica; domínio de termos técnicos.  
- O desafio de evitar o sobreajuste (Overfitting) 
 
Etapa 1 (Esquerda): O Pré-treinamento (Pre-training) 
• Massive dataset (o cilindro de banco de dados): Representa um 
volume gigantesco de textos da internet aberta (artigos, livros, 
notícias, Wikipedia). 
• Pre-trained LLM (o primeiro cérebro): É o modelo que aprendeu o 
idioma, gramática e raciocínio básico a partir desses dados 
massivos. Ele é inteligente, mas ainda é generalista (sabe de tudo 
um pouco). 
  Etapa 2 (Centro): O Ajuste Fino (Fine-tuning) 
• Domain-specific dataset (as folhas de papel embaixo): São os 
dados focados na sua área de negócio (por exemplo: contratos 
jurídicos da sua empresa, prontuários médicos ou transcrições de 
suporte ao cliente). 
• Fine-tuning (a seta do meio): É o processo de alimentar o modelo 
pré-treinado com esses dados específicos. 
• Fine-tuned LLM (o cérebro azul com documentos): É o produto 
final. Ele mantém toda a inteligência do cérebro inicial, mas agora 
sabe responder exatamente com os termos, estilo e regras daquele 
domínio específico. 

=====PAGE=====
  Etapa 3 (Direita): A Interação com o Usuário 
• User (Usuário) ⇄ Fine-tuned LLM: 
o O usuário envia uma pergunta ou instrução (Query). 
o O modelo especialista responde (Response) com precisão 
muito maior do que um modelo comum conseguiria.

11: Parameter Efficient Fine- Tning: 
->Essa metodologia é particularmente relevante para modelos grandes e 
complexos, como os baseados em Transformer em tarefas de 
Processamento de Linguagem Natural (PLN). O objetivo do PEFT é obter

reajustar extensivamente todos os parâmetros do modelo, o que pode ser 
computacionalmente caro e demorado.

15: RAG - Retrieval-Augmented Generation (ou Geração Aumentada de 
Recuperação)  
->É o processo de otimizar a saída de um grande modelo de linguagem 
(LLM), de forma que ele faça referência a uma base de conhecimento 
confiável fora das suas fontes de dados de treinamento antes de gerar 
uma resposta. 
-> É uma abordagem econômica para melhorar a produção do LLM, de 
forma que ele permaneça relevante, preciso e útil em vários contextos. 
->O objetivo é criar bots que possam responder às perguntas dos usuários 
em vários contextos, utilizando-se de fontes de conhecimento confiáveis.

=====PAGE=====
1. transformers — O Cérebro (O Modelo) 
• O que faz: É a biblioteca principal da Hugging Face. É ela quem faz o 
download do modelo (como o Llama) e gerencia a inteligência dele 
(arquitetura, atenção e pesos). 
• Na prática: Sem ela, você não tem o modelo pré-treinado. 
2. bitsandbytes — O Compactador (Economizador de Memória) 
• O que faz: Ele "esmaga" o tamanho dos números do modelo de 16 
bits para 4 bits (técnica chamada de Quantização). É graças a ele 
que conseguimos carregar um LLM gigante em uma GPU comum. 
3. peft — O "Post-it" Inteligente (Técnica LoRA) 
• O que faz: Parameter-Efficient Fine-Tuning. Em vez de retreinar 
todos os 7 bilhões de parâmetros (o que demoraria dias e exigiria 
supercomputadores), o PEFT congela o modelo original e treina 
apenas uma folha de anotações fininha por cima (os adaptadores 
LoRA, menos de 1% do modelo). 
4. accelerate — O Maestro do Hardware 
• O que faz: Gerencia a comunicação entre o código e a GPU. Ele 
decide como alocar a memória de vídeo, fazer cálculos em precisão 
mista (FP16/BF16) e otimizar o fluxo de dados.

Diferença entre SetencePiece x Chunks: 
=====PAGE=====
--> SentencePiece (Escala MICRO — Fatias de Letras) 
• O que fatia: Uma única palavra em pedacinhos de letras 
(subpalavras). 
 
--> Chunks (Escala MACRO — Fatias de Parágrafos) 
• O que fatia: Um documento ou livro inteiro em blocos de texto. 
 
Ex: um pdf se eu cortar em várias parte é chunks (blocos). Para o pc 
conseguir guardar esses chunks guardar esses chunks no banco de dados 
vetorial ou fazer o LLM ler a resposta, o SentencePiece entra em ação 
para traduzir cada palavra desses chunks em números (tokens). 
• SIMILARIDADE x SEMÂNTICO: 
Léxico: "Quero exatamente essas palavras/termos iguais." 
• Semântico: "Quero textos que falem sobre este mesmo 
assunto/significado, mesmo que usem palavras diferentes." 
• Similaridade: É a pontuação (o cálculo) que diz o quão perto ou 
parecido um texto está do outro. 
-> Na computação/IA, eles não chamam palavra exata de "similaridade". 
Eles chamam de LÉXICA (ou busca por palavra-chave).  
-> HÍBRIDO: a busca por palavras exatas (letras iguais) + semântico e 
similaridade.

=====PAGE=====

• ROUGE-1: Palavras soltas (unigramas). Vê se as palavras-chave

• ROUGE-S: Pega pares de palavras na ordem certa, permitindo outras 
palavras no meio. (ex: na frase "o gato preto dormiu", avalia o par 
"gato ... dormiu"). Mede a coesão.

Mód12 - Criando aplicações com LangChain: 
-> LangChain é uma biblioteca (framework), escrita principalmente em 
Python (também existe para JavaScript/TypeScript), que facilita criar 
aplicações com modelos de IA, como o ChatGPT.  (construir aplicações 
com LLMs). Componentes centrais: 
• Abstrações para LLMs: Interface consistente para conectar 
diferentes provedores (OpenAI, Anthropic, Cohere). 
• Chains: Sequências de operações que combinam LLMs e outras 
utilidades para processar entradas e saídas. 
• Agents: Abstrações autônomas que usam o LLM para decidir 
dinamicamente quais ferramentas ou cadeias executar. 
• Memory: Guarda o histórico de interações e estados intermediários 
entre cadeias e agentes. 
• Tools: Integrações com APIs e ferramentas externas (ex.: Wikipedia, 
Python REPLs) para execução de tarefas. 
• Prompts: Utilitários para gestão e otimização de instruções para o 
modelo. 
• Vectorstores e Retrievers: Suporte a bancos vetoriais e busca 
semântica para recuperação eficiente de dados. 
Ou seja, O LangChain oferece uma estrutura modular flexível para o 
desenvolvimento e prototipagem de aplicativos com LLMs. Ele padroniza 
Abstrações para LLMs de diversos provedores e conecta processos via 
Chains. Para comportamentos autônomos, utiliza Agents integrados a 
Tools (APIs externas) e Memory (histórico de estado). O fluxo é otimizado 
por utilitários de Prompts e mecanismos de Vectorstores e Retrievers 
para busca semântica, permitindo iterar e substituir componentes 
=====PAGE=====
facilmente em sistemas como agentes de conversação e fluxos 
automatizados.

11: Simple sequential chain 
-> O que o Simple Sequential Chain faz é transformar a RESPOSTA do 
Robô 1 na ENTRADA (o assunto) do Robô 2. 
Porque, para um modelo de inteligência artificial (LLM), qualquer texto que 
ele recebe para processar é chamado de Entrada (ou Prompt). 
Então: 
• A saída (resposta) do Robô 1 ➔ vira o assunto (entrada) sobre o 
qual o Robô 2 vai trabalhar. 
 
12 sequential-chain: 
-> Nesse pode ter múltiplas entradas e múltiplas saídas ao longo do 
processo. 
A diferença real NÃO é a quantidade de etapas (Chain 1, Chain 2, Chain 
3...), mas sim quantas informações viajam ao mesmo tempo: 
*Simple = Passa apenas 1 informação por vez de robô para robô (estilo 
telefone sem fio). 
*Sequential (Completo) = Passa múltiplas informações simultâneas e 
guarda o histórico de todas as respostas que você quiser. 
 
13 criando memória para o LLM: 

=====PAGE=====
-> O Buffer no LangChain é uma das formas mais comuns de dar memória 
para o LLM (como o ChatGPT), permitindo que ele lembre das mensagens 
anteriores durante uma conversa. 
ConversationBufferMemory x ConversationBufferWindowMemory: 
• ConversationBufferMemory: Armazena a íntegra de todo o histórico da 
sessão, garantindo retenção total de contexto ao custo de um aumento 
progressivo no consumo de tokens e na latência. 
• ConversationBufferWindowMemory: Retém apenas as K interações mais 
recentes através de uma janela deslizante, otimizando custos e tempo de 
resposta em conversas extensas ao descartar contextos antigos. 
• Ou seja, ConversationBufferMemory é como um caderno onde 
você escreve todas as páginas da conversa. A cada nova pergunta, o 
robô re-lê o caderno inteiro desde a página 1. 
• ConversationBufferWindowMemory é como uma lousa pequena 
onde só cabem as últimas 3 frases. Para escrever uma nova frase, 
você precisa apagar a frase mais antiga da lousa. Então, podemos 
limitar o contexto de memória.

06 Consulta e recuperação em Vector:

parecidas.

 07 Reasoning: 
->Reasoning (Raciocínio) em LLMs: 
É a capacidade dos (LLMs) de fazer deduções lógicas e resolver 
problemas usando as informações que aprenderam durante o 
treinamento. 
-1-Como funciona o Raciocínio (Componentes-chave) = 
• Inferência Lógica: O modelo reconhece padrões no texto para tirar 
conclusões óbvias (ex: se todo cão é mamífero e Rex é um cão, Rex é 
mamífero). 
• Resolução de Problemas: Consegue seguir múltiplas etapas para 
resolver questões de matemática, gerar códigos ou responder 
perguntas difíceis. 
• Compreensão de Contexto: Avalia a situação em que a pergunta foi 
feita para dar respostas que façam sentido. 
• Generalização: Consegue aplicar o que aprendeu em uma área para 
outra (ex: usar regras gramaticais do inglês para ajudar a entender 
outro idioma). 
=====PAGE=====
2. Tipos de Raciocínio (Exemplos) = 
• Dedutivo: Parte de uma regra geral para chegar a uma conclusão 
específica. 
• Indutivo: Observa vários casos específicos para criar uma regra 
geral (ex: João e Ana estudaram e passaram, logo, estudar ajuda a 
passar). 
• Estratégico: Alguns modelos conseguem resolver quebra-cabeças 
complexos ou jogar xadrez. 
3. Limitações e Desafios = 
• Depende 100% dos Dados: O raciocínio do LLM só será bom se os 
dados que ele usou para treinar forem bons. Dados incompletos ou 
preconceituosos geram respostas ruins. 
• Falta de Contexto: Eles podem se perder em situações muito sutis 
ou específicas que não viram no treinamento. 
• "Alucinações" / Interpretação Errada: Às vezes, eles simplesmente 
interpretam as coisas de forma errada e chegam a conclusões 
incorretas baseadas em premissas falsas. 
--> Então, o modelo não "pensa" como um humano, ele calcula a 
probabilidade matemática de qual palavra (token) deve vir a seguir com 
base em padrões gigantescos, o que muitas vezes simula com perfeição 
um raciocínio lógico! 
 
10- Criando tokenizador: 
-> LLMs não sabem fazer matemática nem raciocinar.  Os modelos de 
linguagem (como Transformers) apenas prevêem o próximo token. 
Ex: 9 + 5 = 14 da erro       / 9 + 5 = 1  4 agora da certo 
• Padding (Preenchimento): Redes neurais exigem entradas de 
tamanho fixo. O padding (valor -1) serve para preencher os espaços 
vazios de sequências mais curtas, garantindo que todas tenham o 
mesmo tamanho. 
• Encoder e Decoder: O modelo só entende números. O Encoder 
(codificador) converte o texto para números (IDs) para a IA 
=====PAGE=====
processar. O Decoder (decodificador) pega a resposta em números 
da IA e converte de volta para texto para nós lermos. 
• Métodos (__call__ e decode): Na prática, o __call__ aplica o 
Encoder (codifica) e o método decode aplica o Decoder (decodifica). 
20: 
Encoder: converte a string de entrada para o token correspondente, 
enquanto o Decoder faz ao contrário.  
-> O Modelo não trabalha com strings, mas sim com valores números que 
é o resultado do valor do token.

04: Agentes de IA 
-> Agentes de Inteligência Artificial (IA) são programas de software 
baseados em LLMs projetados para interagir com seu ambiente, coletar 
dados e utilizá-los para realizar tarefas de forma autônoma, visando

05 Agentes de IA são RPA 2.0? 
-> Não exatamente, Agentes de IA não são apenas uma atualização do 
RPA, mas uma mudança de paradigma: substituem regras fixas por 
raciocínio e adaptação autônoma. 
->RPA Tradicional: Focado na automação de tarefas repetitivas e 
baseadas em regras fixas. Ele replica cliques e digitações humanas no 
sistema, funcionando de maneira determinística (se a interface mudar ou 
houver exceções não mapeadas, ele falha). 
-> Agentes de IA: Sistemas dotados de autonomia, capazes de raciocinar, 
tomar decisões, planejar e se adaptar a contextos dinâmicos e dados não 
estruturados (textos, imagens, linguagem natural). 
 
10 Componentes principais de um agente de IA: 
• Os sensores (entrada e percepção) permitem que o agente colete 
dados de seu ambiente. 
• Um processador (cérebro e tomada de decisão) analisa esses 
dados e toma decisões com base neles. 
• Os atuadores (ação e saída) são os meios pelos quais o agente 
afeta o ambiente, executando as ações decididas pelo 
processador.  
LLMs são os processadores mais comuns para agentes de IA 
atualmente.

• O Re-Ranking funciona como uma segunda etapa de filtragem

los ao modelo gerador (LLM): 
=====PAGE=====

completa. Isso gera uma nota de relevância (score) muito mais 
precisa e fiel ao sentido real da consulta.

04 Fundamentos da teoria dos Grafos: 
▫ Um grafo é uma forma de representar um caminho entre etapas. 
Ou seja, todas as etapas conectadas pelos caminhos. 
▫ Nó = uma etapa (ex.: pesquisar, responder, resumir). 
▫ Aresta = o caminho entre uma etapa e outra. 
 
--> A Teoria dos Grafos é um ramo da matemática que estuda 
relações entre objetos, representadas por estruturas chamadas 
grafos. Um grafo é composto por vértices (ou nós) e arestas (ou 
ligações) que conectam esses vértices. 
05: LangGraph e construção de agentes: 
=====PAGE=====
-> É uma biblioteca construída sobre o LangChain, ou seja, aproveita 
as ferramentas e adiciona a capacidade de orquestrar fluxos com 
decisões e loops. 
--> A biblioteca introduz a ideia de modelar fluxos de trabalho como 
grafos cíclicos, adicionando memória embutida – recursos 
fundamentais para agentes autônomos. 
Ou seja, grafo é só um jeito de desenhar o fluxo: caixinhas 
conectadas por setas. Cíclico é porque, se precisar, o fluxo pode 
voltar para um passo anterior. Já a memória embutida significa que o 
LangGraph lembra o que já aconteceu durante a execução. Tipo: já 
pesquisei antes, então posso mudar de estratégia sem perguntar 
tudo de novo. 
Juntando isso, você cria agentes que conversam, repetem etapas 
quando precisa e mantêm contexto, que é justamente o que dá 
inteligência e flexibilidade para o sistema. É como se o workflow não 
fosse só uma linha reta, mas um caminho que aprende enquanto 
anda. 
-> Um agente com LangGraph pode planejar, decidir, pesquisar, 
consultar, talvez chamar outro modelo, checar se deu certo e, se 
não deu, repetir. Ele não fica só conversando, ele executa um 
processo para chegar num objetivo. Essa é a grande virada de chave 
entre chatbot e agente de IA.  
Então, o LangGraph ele gerencia, ele apenas coordena.

14 O que é um Workflow no LangGraph: 
-> No LangGraph, um workflow é a estrutura que organiza como LLMs 
(modelos de linguagem) e ferramentas trabalham juntos para executar 
uma tarefa. Existem dois tipos principais: 
• Workflows com caminhos predefinidos: seguem uma sequência 
de etapas já definida pelo desenvolvedor. 
• Agentes com controle dinâmico: o próprio LLM decide, durante a 
execução, quais ações e ferramentas utilizar conforme a 
necessidade. 
-> O LangGraph suporta ambos os modelos, permitindo criar desde fluxos 
lineares simples até arquiteturas complexas com múltiplos agentes 
colaborando de forma dinâmica. 
Além disso, oferece persistência de contexto (para manter informações 
em interações longas) e suporte nativo a streaming, exibindo em tempo 
real o raciocínio e as ações dos agentes. 
--> Em resumo, um workflow no LangGraph é a estrutura que define e 
organiza a interação entre os componentes de IA para executar tarefas 
com flexibilidade e controle.

21 Configuração Multi-Agente e Humain in the loop: 
-> A Configuração Multi-Agente no LangGraph refere-se ao uso de vários 
agentes dentro de um único grafo para colaborar e resolver tarefas 
complexas. Cada agente pode ter um papel específico e interagir 
dinamicamente no fluxo do grafo. 

=====PAGE=====
-> O Human-in-the-Loop (HITL) é uma abordagem onde humanos intervêm 
no fluxo do agente quando necessário. Isso é útil em casos que exigem 
supervisão, validação ou decisões que um modelo sozinho não pode 
tomar. 
-> Para facilitar a implementação de interações humanas, o LangGraph 
introduziu a função interrupt. Essa função permite pausar a execução do 
fluxo de trabalho em um ponto específico, apresentar informações ao 
usuário e, posteriormente, retomar o processo com base na entrada 
fornecida pelo humano. 
Os principais padrões são: 
 Aprovar ou rejeitar: antes de ações críticas (como uma chamada de 
API), o fluxo pode ser pausado para revisão humana. Se a ação for 
rejeitada, o workflow pode seguir um caminho alternativo. 
 Revisar e editar o estado: o humano pode revisar e modificar o 
estado atual do workflow para corrigir erros ou adicionar 
informações. 
 Solicitar entrada: o sistema pode pedir informações adicionais ao 
usuário em pontos específicos do fluxo para esclarecer dúvidas ou 
obter mais contexto. 
-> Para suportar essas intervenções, o LangGraph utiliza checkpoints, que 
salvam o estado do workflow em momentos específicos. Assim, o 
processo pode ser pausado e retomado sem perder o contexto nem 
comprometer a integridade do fluxo.

03 Agentic RAG Integração de Recuperação e Geração com Agentes de 
IA: 
=====PAGE=====
-> Os LLMs (Large Language Models) geram textos com alta qualidade, 
mas podem produzir respostas erradas com muita confiança, fenômeno 
chamado de alucinação. 
Para reduzir esse problema, surgiu o RAG (Retrieval-Augmented 
Generation), que faz o modelo buscar informações em fontes externas 
(como documentos e bases de conhecimento), tornando as respostas 
mais precisas, atualizadas e contextualizadas. 
Porém, o RAG tradicional apenas recupera informações e fornece 
contexto, sem fazer uma análise aprofundada ou definir a melhor 
estratégia de busca. 
Para resolver essa limitação, surgiu o Agentic RAG, que utiliza Agentes de 
IA para analisar, planejar, decidir e priorizar quais informações buscar e 
como utilizá-las. Assim, ele vai além da simples recuperação de dados, 
realizando uma interação mais inteligente e ativa com o conhecimento 
disponível. 
04 Fundamentos e limitações do RAG tradicional: 
-> Limitações do RAG Tradicional (Vanilla RAG) 
• Uma única fonte: normalmente consulta apenas uma base de 
conhecimento, dificultando combinar informações de várias fontes. 
• Processo one-shot: faz apenas uma busca por consulta, sem 
validar ou refazer a pesquisa caso os documentos recuperados não 
sejam os melhores. 
• Dificuldade em priorizar informações: pode trazer muitos dados 
pouco relevantes e não destacar as informações mais importantes 
ou especializadas. 
• Compreensão limitada do contexto: recupera documentos 
relacionados, mas nem sempre entende quais realmente 
respondem à intenção do usuário ou como integrá-los de forma 
coerente. 
=====PAGE=====
➡Essas limitações levaram ao surgimento do Agentic RAG, que 
adiciona Agentes de IA capazes de planejar, raciocinar, escolher fontes, 
priorizar informações e realizar novas buscas quando necessário, 
tornando as respostas mais inteligentes e precisas. 
05 Agentes de IA e raciocínio autônomo: 
- Características dos Agentes de IA 
• LLM com um papel definido e uma tarefa alvo. 
• Memória, que pode armazenar informações do diálogo e de tarefas 
anteriores (curto e longo prazo). 
• Planejamento e raciocínio, usando técnicas como Chain of 
Thought (CoT) e ReAct, permitindo dividir problemas complexos em 
etapas e ajustar a estratégia. 
• Uso de ferramentas externas (Tool Use), como buscadores, 
calculadoras, bancos de dados e APIs (e-mail, calendário, etc.), 
ampliando suas capacidades. 
Ciclo Percepção-Ação (ReAct) 
O agente funciona em um ciclo contínuo: 
Pensamento → Ação → Observação → (repete o ciclo, se necessário) → 
Resposta final 
• Pensamento: decide a melhor estratégia. 
• Ação: utiliza uma ferramenta ou executa uma tarefa. 
• Observação: analisa o resultado obtido. 
• Repetição: ajusta a estratégia e realiza novas ações até encontrar 
uma solução satisfatória. 
• Resposta final: entrega a melhor resposta ao usuário. 
Diferença para um LLM comum 
• LLM tradicional: recebe a pergunta e responde em uma única 
passada (one-shot). 
=====PAGE=====
• Agente de IA: raciocina, planeja, usa ferramentas, observa 
resultados e pode repetir o processo antes de responder, gerando 
respostas mais completas e precisas. 
➢ ReAct: é uma técnica/framework que permite que um Agente de 
IA pense, execute ações e analise os resultados antes de dar a 
resposta final. 
➢ Chain of Thought (CoT): é uma técnica que faz o LLM raciocinar 
passo a passo antes de chegar à resposta final. (corrente de 
pensamento) 
08 Arquitetura e Funcionamento do Agentic RAG Agente Único vs. 
Múltiplos Agentes:  
1. Agentic RAG com Agente Único (Router) 
• Possui um único agente central responsável por controlar todo o 
processo. 
• Esse agente funciona como um roteador inteligente, decidindo: 
o Qual fonte de conhecimento consultar (documentos internos, 
Web, banco de dados etc.). 
o Se precisa buscar informações ou se já consegue responder 
com o conhecimento disponível. 
• Ele realiza raciocínio, busca e geração da resposta sozinho. 
Vantagem: arquitetura mais simples e flexível. 
Limitação: toda a responsabilidade fica em um único agente, que precisa 
lidar com diferentes tipos de tarefas. 
2. Agentic RAG Multiagente 
• Utiliza vários agentes especializados que trabalham em conjunto. 
• Existe um agente mestre (coordenador) que: 
o Recebe a pergunta do usuário. 
o Divide a tarefa em subtarefas. 
o Distribui as tarefas para agentes especializados. 
o Junta os resultados e gera a resposta final. 
=====PAGE=====
Exemplo: Uma pergunta pode exigir: 
• Agente de dados internos: busca informações da empresa. 
• Agente de dados pessoais: consulta histórico do usuário. 
• Agente de busca externa: pesquisa informações públicas. 
Cada agente resolve sua parte e o agente mestre combina tudo. 
Vantagens: 
• Maior eficiência. 
• Respostas mais completas. 
• Permite escalar tarefas dividindo responsabilidades. 
 
Outros tipos de agentes dentro do pipeline 
Além dos agentes de recuperação de informação, podem existir agentes 
especializados em: 
• Routing Agent: direciona perguntas para o caminho correto. 
• Query Planning Agent: quebra perguntas complexas em partes 
menores e planeja as buscas. 
• Quality Control Agent: revisa respostas e verifica possíveis erros. 
• Formatting Agent: organiza os dados em uma resposta mais clara 
para o usuário. 
 
09 Re-Ranking: 
Re-ranking é uma técnica usada após a busca inicial de informações para 
reorganizar os resultados, colocando em primeiro lugar os documentos 
ou trechos mais relevantes para a pergunta do usuário. 
Como funciona: 
1. Busca inicial (retrieval): 
a. O sistema recupera vários documentos usando métodos 
rápidos, como embeddings e similaridade semântica. 
=====PAGE=====
b. O objetivo é encontrar possíveis informações relevantes. 
2. Re-ranking: 
a. Um modelo mais avançado analisa esses resultados. 
b. Ele reorganiza os documentos considerando critérios como: 
relevância; qualidade; precisão; contexto da pergunta. 
3. Geração da resposta: 
a. O LLM recebe os conteúdos mais importantes e gera uma 
resposta mais precisa. 
Vantagem do Re-ranking: 
• Velocidade: da busca inicial por embeddings. 
• Precisão: da análise mais profunda de modelos avançados. 
Assim, reduz informações irrelevantes e garante que o LLM tenha acesso 
aos melhores dados disponíveis.

15 Normalização de Embeddings: 
-> Em RAG, os embeddings são representações vetoriais de texto 
(palavras, frases, documentos). Eles capturam o significado semântico do 
texto, permitindo que o sistema compare a similaridade entre diferentes 
textos.  
Modelos como OpenAI Embeddings, Sentence Transformers ou outros 
modelos de linguagem são usados para gerar esses embeddings. 
-> É o processo de ajustar todos os vetores de embedding para que 
tenham o mesmo comprimento padrão (tamanho = 1), preservando 
apenas a direção para onde apontam. 
• Objetivo: Garantir que a comparação entre textos avalie apenas o 
significado (direção do vetor), e não a extensão do texto ou 
repetição de palavras (tamanho/magnitude). 
• Como funciona: Divide-se o vetor original pela sua própria norma 
(comprimento), transformando-o em um vetor unitário. 
• Vantagem prática: Torna o cálculo de similaridade (como a 
similaridade de cosseno) muito mais justo, preciso e rápido para o 
banco de dados vetorial.

02 Compreendendo o Conceito de Encadeamento de Prompts (Prompt 
Chaining): 
 
-> O encadeamento de prompts é uma técnica utilizada ao interagir com 
modelos de linguagem de grande escala (LLMs). A ideia central é usar a 
saída (resposta) de um prompt como entrada (ou parte da entrada) para o 
próximo prompt, criando assim uma sequência ou "cadeia" de interações. 
 
-> Por que usar usar o Encadeamento de Prompts?  
✓ Decompor Tarefas Complexas 
✓  Refinar Resultados 
=====PAGE=====
✓  Manter o Contexto (Controlado): Ajuda a guiar o LLM através de um 
fluxo de trabalho específico, garantindo que a informação relevante 
da etapa anterior seja explicitamente passada para a próxima. 
✓  Combinar Habilidades: Permite combinar diferentes "habilidades" 
do LLM.  
✓ Automatizar Fluxos de Trabalho: Sequências de prompts podem ser 
programadas para automatizar processos que requerem múltiplas 
etapas de geração ou análise de texto.  
 
 Propagação de Erros: Se um erro ocorrer em uma etapa inicial, ele 
pode afetar negativamente as etapas subsequentes. 
 Gerenciamento: Cadeias muito longas podem se tornar complexas 
de gerenciar e depurar.  
 Custo/Latência: Cada prompt na cadeia representa uma chamada 
separada para o LLM, o que pode aumentar o tempo total e o custo, 
se aplicável. 
 
04 - Integração de Prompt Chaining com RAG Para Maior Eficácia: 
 
Recapitulando os Conceitos: 
I. Prompt Chaining: Criar uma sequência de prompts onde a saída de 
um passo alimenta o próximo.  
II.  RAG (Retrieval-Augmented Generation): Antes de gerar uma 
resposta, o sistema busca (retrieve) informações relevantes em uma 
base de conhecimento externa. Essas informações recuperadas são 
então fornecidas ao LLM junto com o prompt original para que ele 
gere uma resposta "aumentada" e fundamentada nesses dados 
externos.  
 
Ideia Central: O RAG não precisa estar em todas as etapas da cadeia. Ele 
é acionado apenas nos passos onde o LLM precisa consultar dados 
externos e específicos. 
Fluxo Típico em 3 Passos: 
1. Passo 1 — Prompt Puro (LLM): 
=====PAGE=====
a. O modelo processa uma entrada inicial ou toma uma decisão. 
b. Exemplo: Identifica qual cliente teve mais chamados. 
2. Passo 2 — Encadeamento + RAG (Busca Externa): 
a. A saída do passo anterior define o que buscar na base de 
conhecimento. 
b. Retrieve: Busca os dados externos (ex.: chamados daquele 
cliente no CRM). 
c. Augment & Generate: O LLM lê esses dados e gera uma 
resposta (ex.: resume os problemas relatados). 
3. Passo 3 — Próxima Ação (Puro ou novo RAG): 
a. A saída do passo 2 alimenta a próxima etapa: 
i. Puro: O LLM apenas raciocina sobre o resumo (ex.: 
sugere categorias para os problemas). 
ii. RAG: O LLM dispara uma nova busca externa (ex.: busca 
artigos na base de soluções para resolver o problema 
identificado). 
Em resumo: O Prompt Chaining cria o fluxo lógico (passo a passo), e o 
RAG entra pontualmente como uma "ferramenta de consulta" quando o 
LLM precisa de dados reais e atualizados para avançar.

Cadeia de pensamento = 
-> É uma técnica de prompting (ou seja, uma forma de dar instruções)

->  O objetivo principal é melhorar a capacidade do modelo de raciocinar

=====PAGE=====

-> É o processo de direcionar uma tarefa específica para o Agente de IA 
mais adequado para executá-la dentro de um sistema que contém 
múltiplos agentes. Ou seja, é o mecanismo de decisão de caminho. 
• Uma nova tarefa (um pedido, uma pergunta, um problema) chega ao 
sistema.  
• O "roteador" (que pode ser ele mesmo um agente simples ou um 
conjunto de regras) analisa a tarefa.  
• Com base nas características da tarefa e nas capacidades 
conhecidas dos diferentes Agentes de IA disponíveis, o roteador 
decide qual agente é o melhor para lidar com aquela tarefa 
específica. A tarefa é então enviada para o agente selecionado ou 
para o LLM adequado. 
-> Uma das vantagens de usar roteador é a resiliência: Se um agente 
falhar, o roteador pode (dependendo da configuração) redirecionar a 
tarefa para outro agente capaz.

5 Etapas para Configurar Roteamento de Agentes 
1. Mapear Agentes e Capacidades 
• Catálogo: Listar agentes com suas especialidades, limitações e

2. Classificar as Tarefas de Entrada

• Por ML / Semântica: Classificador ou busca vetorial (embeddings)

• Híbrida: Combina métodos (ex: filtra por habilidade e desempata 
pelo menos ocupado).  = palavras-chave exatas + busca semântica 
por significado.

mensagens.

1- Modelos Intrinsecamente Explicáveis ("Caixa de Vidro") 
São modelos simples por natureza. A própria fórmula ou lógica interna já 
é aberta e fácil de auditar. 
• Analogia: Um fluxograma ou uma receita de bolo passo a passo. 
 
1. Métodos Pós-Hoc ("Raio-X da Caixa-Preta") 
Usados quando o modelo é muito complexo (como redes neurais 
profundas) e não conseguimos enxergar seu interior diretamente.  
A técnica é aplicada depois (post-hoc) que o modelo já foi treinado. 
Dois dos métodos mais famosos: 
❖ LIME (Local Interpretable Model-agnostic Explanations): 
=====PAGE=====
o O que faz: Foca em decisões pontuais/individuais. 
o Como funciona: Explica por que o modelo tomou aquela 
decisão específica para aquele caso (ex.: "Por que o cliente 
João teve o crédito negado hoje? Porque a variável 'dívidas 
recentes' pesou negativamente"). 
• Vantagens: 
o Agnóstico ao Modelo: Funciona com qualquer algoritmo 
(redes neurais, florestas, etc.) sem precisar saber como ele foi 
feito por dentro. 
o Intuitivo: A lógica de "aproximar o redor de um ponto com uma 
linha reta" é muito fácil de entender. 
o Flexível: Aceita dados tabulares (planilhas), textos e imagens. 
o Mais Rápido: Geralmente é mais rápido para gerar uma 
explicação pontual do que calcular valores exatos de Shapley. 
• Desvantagens: 
o Instabilidade: Como gera perturbações aleatórias, rodar o 
LIME duas vezes para o mesmo dado pode gerar explicações 
ligeiramente diferentes. 
o Definição da Vizinhança: Definir o que é "perto" do ponto 
analisado é uma escolha arbitrária que pode mudar o 
resultado. 
o Apenas Local: Não te dá a visão global de como o modelo 
inteiro funciona. 
o Fidelidade Limitada: Se a decisão do modelo naquele ponto 
for muito complexa/curva, uma reta simples (modelo 
aproximado) não vai refletir a realidade com exatidão. 
 
❖ SHAP (SHapley Additive exPlanations): 
o O que faz: Baseia-se na Teoria dos Jogos (Valores de 
Shapley). 
o Como funciona: Trata cada característica de entrada como 
um jogador em uma equipe e mede exatamente quanto cada 
uma contribuiu para afastar a previsão final da média de 
referência. 
• Vantagens: 
=====PAGE=====
o Fundamentação Matemática Sólida: Baseado em princípios 
formais (Valores de Shapley), garantindo justiça e a 
propriedade de aditividade (a soma dos impactos bate 
exatamente com o resultado final). 
o Local e Global: Explica tanto uma linha individual quanto o 
comportamento de todo o modelo quando agregamos as 
análises. 
o Mais Robusto e Estável: Não sofre da aleatoriedade do LIME; 
o resultado é consistente. 
o Excelentes Visualizações: Possui gráficos ricos e 
consagrados no mercado (beeswarm plots, force plots, 
waterfall plots). 
• Desvantagens: 
o Alto Custo Computacional: Comparar todas as combinações 
possíveis exige muito processamento (o KernelSHAP pode ser 
muito lento em bases grandes, embora existam versões 
otimizadas como TreeSHAP para árvores e DeepSHAP para 
redes neurais). 
o Curva de Aprendizado: Interpretar seus gráficos e 
fundamentos exige mais conhecimento técnico. 
o Suposição de Independência: Algumas versões assumem 
que as variáveis não dependem umas das outras, o que nem 
sempre é verdade na prática.

17 Estado do agente: 
class AgentState(TypedDict): 
o Cria a classe AgentState, que herda de TypedDict. 
o TypedDict define um dicionário com estrutura e tipos pré-
definidos, permitindo verificação estática de tipos. 
o O objetivo é representar o estado do agente com um formato 
bem definido. 
messages: Annotated[List[BaseMessage], operator.add] 
o messages é um campo (chave) do AgentState. 
o List[BaseMessage] indica que esse campo deve ser uma lista de 
objetos BaseMessage (ou subclasses), garantindo que apenas 
mensagens válidas sejam armazenadas. 
Annotated[...] 
o Permite adicionar metadados a um tipo sem alterar seu 
funcionamento. 
o O primeiro argumento é o tipo real (List[BaseMessage]). 
o Os demais argumentos são metadados usados por bibliotecas, 
como o LangGraph. 
operator.add 
o É o metadado associado ao campo messages. 
o No LangGraph, informa como atualizar esse campo: novas 
mensagens não substituem as antigas, mas são concatenadas à 
lista existente, como em lista1 + lista2. 
=====PAGE=====
o Esse comportamento funciona como a memória do agente, 
preservando o histórico de mensagens ao longo da conversa.

02- Deep Research na IA Generativa: 
-> Deep Research (Pesquisa Profunda) é a capacidade de uma IA 
Generativa realizar uma investigação detalhada e complexa antes de gerar 
uma resposta. Não é um termo técnico oficial como RAG ou Fine-Tuning, 
mas descreve um processo mais avançado de pesquisa. 
  
Principais características: 
* Consulta múltiplas fontes: pesquisa em artigos científicos, bancos de 
dados, notícias, documentos internos, páginas da web etc. 
* Recuperação avançada de informações: usa técnicas sofisticadas 
(geralmente baseadas em RAG) para encontrar conteúdos altamente 
relevantes. 
* Pesquisa em várias etapas: divide perguntas complexas em 
subperguntas, faz buscas iterativas, analisa resultados, identifica lacunas 
e busca novas informações. 
* Síntese e raciocínio: compara, relaciona e combina informações de 
diferentes fontes para formar uma resposta completa e coerente. 
* Contextualização: utiliza as informações encontradas para gerar 
respostas mais profundas, precisas e bem fundamentadas. 
* Confiabilidade: prioriza fontes confiáveis para reduzir erros e 
alucinações da IA. 
=====PAGE=====
Diferença para o RAG:  
* RAG simples: recupera alguns trechos relevantes para responder à 
pergunta. 
* Deep Research: realiza uma pesquisa completa, iterativa e semelhante 
ao trabalho de um pesquisador humano, analisando diversas fontes antes 
de gerar a resposta. 
03-Quando usar Deep Research? 
  
-> O Deep Research deve ser usado quando uma resposta simples ou 
apenas o conhecimento pré-treinado da IA não são suficientes. Ele é 
indicado para tarefas que exigem: 
  
* Perguntas complexas e multifacetadas: quando é necessário analisar 
diferentes perspectivas, fatores e informações de várias áreas. 
    Exemplo: impacto das mudanças climáticas na agricultura brasileira 
considerando aspectos econômicos, sociais e tecnológicos. 
* Alta precisão e confiabilidade: em situações críticas onde erros podem 
causar consequências importantes. 
    Exemplo: decisões médicas, análises financeiras ou pesquisas jurídicas. 
* Informações específicas ou de nicho: quando o assunto é muito 
especializado, recente ou pouco presente nos dados gerais da IA. 
    Exemplo: novas tecnologias, doenças raras ou processos internos de 
empresas. 
* Informações recentes ou dinâmicas: quando é necessário usar dados 
atualizados, eventos recentes ou tendências atuais. 
    Exemplo: mercado, notícias ou mudanças recentes em uma área. 
* Produção de conteúdos aprofundados: para criar relatórios, artigos, 
análises ou documentos baseados em pesquisas e fontes confiáveis. 
=====PAGE=====
* Fact-checking (verificação de fatos): para confirmar informações 
comparando diferentes fontes externas confiáveis. 
* Redução de limitações e vieses da IA: para complementar o 
conhecimento do modelo com informações externas mais diversas e 
específicas. 
  
—> Resumo: O Deep Research é usado quando a tarefa exige mais 
profundidade, precisão, atualidade, especificidade ou complexidade do 
que uma resposta comum da IA ou uma busca simples/RAG conseguem 
oferecer. Ele amplia a capacidade da IA por meio de pesquisa e análise de 
informações externas confiáveis.

02 MCP: 
=====PAGE=====
-> É um protocolo de comunicação, ou seja, um padrão que permite que 
aplicações de IA se conectem a ferramentas e fontes de dados de forma 
padronizada. Ele não é uma técnica de IA. 
• Primitivas Chave (Capacidades Expostas pelos Servidores) 
-> Os Servidores MCP expõem suas funcionalidades através de três 
primitivas principais: 
o Ferramentas (Tools). 
o Recursos (Resources): Representam dados contextuais que são 
anexados e gerenciados pela aplicação cliente (Host).   
o Prompts: São instruções pré-definidas. 
• Componentes do MCP 
1. Host MCP 
• É a aplicação onde o usuário interage com a IA (como ChatGPT, um 
IDE ou um sistema próprio). 
• Atua como o coordenador central da comunicação. 
• Cria e gerencia os Clientes MCP. 
• Define quais Servidores MCP os clientes podem acessar. 
• Aplica políticas de segurança, permissões e privacidade. 
2. Cliente MCP 
• Opera sob o controle do Host. 
• Cada Cliente MCP estabelece uma conexão um-para-um com um 
Servidor MCP específico. 
• Traduz as solicitações do Host para o protocolo MCP. 
• Envia as mensagens ao Servidor MCP e devolve as respostas ao 
Host. 
3. Servidor MCP 
• Conecta-se a uma ferramenta ou fonte de dados específica. 
• Expõe suas capacidades ao agente por meio do protocolo MCP. 
• Essas capacidades podem incluir: 
=====PAGE=====
o Tools (Ferramentas): executar ações, como pesquisar 
arquivos, enviar mensagens ou consultar um banco de dados. 
o Resources (Recursos): disponibilizar dados ou informações 
para o modelo. 
o Prompts: instruções pré-definidas que podem orientar o 
comportamento do modelo em determinadas tarefas. 
• Exemplos de servidores: Google Drive, GitHub, Slack, bancos de 
dados, APIs e sistemas internos. 
Fluxo de funcionamento 
Usuário → Host → Cliente MCP → Servidor MCP → Ferramenta/Dados → 
Servidor → Cliente → Host → Usuário 
▪ MCP = protocolo de comunicação. 
▪ Host = coordena a comunicação e controla segurança e 
permissões. 
▪ Cliente = faz a ponte entre o Host e um Servidor MCP específico. 
▪ Servidor = conecta a IA às ferramentas e aos dados, expondo 
suas capacidades.

Resumindo para memorizar: 
• LangGraph = orquestração, fluxo de trabalho e gerenciamento de 
estado.

Os dois podem trabalhar juntos para criar agentes mais organizados,

13 - Camadas de Transporte no MCP: 
-> Essas camadas são responsáveis por garantir a comunicação eficiente 
entre Agentes de IA (clientes) e ferramentas externas (servidores), 
utilizando o formato de mensagens JSON-RPC 2.0. Essas camadas

processos no mesmo computador. Já no Streamable HTTP, usa HTTP pela 
rede, com suporte a streaming, tipo enviando pedacinhos da resposta 
conforme fica pronta. O SSE também usa HTTP, mas é mais focado em

-> SSE é uma tecnologia de comunicação unidirecional baseada em HTTP,

real para o cliente de forma contínua, mantendo uma única conexão 
aberta. 
o  Pode ser usado como um transporte quando o agente precisa 
apenas "ouvir" eventos ou respostas de ferramentas longas ou 
assíncronas.

o  Conexão persistente: mantém uma conexão HTTP aberta por tempo 
indefinido, enviando dados conforme necessário.  
=====PAGE=====

reconectar automaticamente.  
o Formato simples: baseado em texto, fácil de debugar e implementar. 
--> Limitações: 
o Apenas servidor → cliente: sem comunicação bidirecional.  
o Sem suporte nativo a envio de binários (tudo é texto).  
o Menor suporte em algumas linguagens/frameworks no backend, em 
comparação a WebSocket ou HTTP stream.

CURSO 03 – RAG, GraphRag e AgenticRag: 
Mód 1 - RAG, Agentic RAG e GraphRAG: 
1. RAG (Retrieval-Augmented Generation) 
-> RAG é uma técnica usada em sistemas de IA para melhorar as respostas 
do modelo usando uma base de conhecimento externa. 
Limitação do RAG tradicional: 
* Ele é muito bom para encontrar informações parecidas. 
* Porém, pode ter dificuldade quando a resposta depende de várias 
relações entre informações diferentes. 
2. Agentic RAG (Agente RAG) 
-> Agentic RAG é uma combinação de agente de IA + RAG. 
A diferença é que ele possui uma camada de decisão. 
• Um RAG tradicional faz: 
Pergunta → Busca → Resposta 
• Um Agentic RAG faz: 
=====PAGE=====
Pergunta → Analisa a tarefa → Decide o que fazer → Usa ferramentas (como 
RAG) → Refina → Responde 
❑ Todo Agentic RAG é um agente, mas nem todo agente é Agentic RAG. 
3. GraphRAG 
-> GraphRAG também é uma técnica baseada em RAG, mas adiciona um 
grafo de conhecimento. 
A ideia é que, além de guardar informações em vetores, o sistema cria 
relações entre entidades. 
Exemplo:   Nós (entidades): 
* João     * Empresa X          * Maria      * São Paulo 
 Arestas (relações):   * João → trabalha na → Empresa X 
* Empresa X → foi fundada por → Maria 
* Maria → mora em → São Paulo 
O grafo representa como as informações estão conectadas. 
 Rag x GraphRAG: 
 Busca principalmente por: 
    Similaridade semântica 
GraphRAG busca por: 
    Similaridade semântica    +              Relações entre entidades  
OBS: LangGraph é diferente de GraphRag, LG é um framework que cria 
fluxo de execução dos agentes, já o GR é uma técnica de recuperação de 
conhecimento. 
Grafo de execução e o outro grafo de conhecimento (GraphRag):   
    LangGraph: grafo = “quais passos o agente vai executar?” 
* GraphRAG: grafo = “como as informações estão relacionadas?” 
-> Os dois usam nós e arestas, mas com objetivos totalmente diferentes.

CAG (Cache-Augmented Generation / Geração Aumentada por Cache) 
  
15  Cache-Augmented Generation (CAG): 
_. O CAG é uma abordagem para otimizar LLMs (modelos de linguagem 
grandes) pré-carregando informações importantes diretamente no 
contexto do modelo, evitando a necessidade de buscar dados durante a 
resposta. 
 Diferente do RAG, que faz uma busca em fontes externas em tempo real 
durante a geração da resposta, o CAG já deixa as informações necessárias 
disponíveis para o modelo usar, aproveitando as janelas de contexto 
maiores dos LLMs modernos. 
•  Como funciona: 
1. As informações relevantes são carregadas previamente no contexto do 
modelo. 
2. O usuário faz uma pergunta. 
3. O LLM responde usando esse conhecimento já disponível, sem precisar 
recuperar dados externamente. 
• Vantagens do CAG: 
* Menor latência: como não precisa fazer uma busca antes de responder, a 
resposta é mais rápida. 
* Maior confiabilidade: usa informações previamente selecionadas e 
verificadas, reduzindo erros de recuperação. 
* Arquitetura mais simples: elimina a necessidade de sistemas complexos 
de busca e recuperação. 
• Limitações do CAG:  
=====PAGE=====
* Tamanho do conhecimento: todo o conhecimento necessário precisa 
caber na janela de contexto do modelo, o que pode ser difícil em bases 
muito grandes. 
* Limite de contexto: textos muito extensos podem prejudicar o 
desempenho do LLM, apesar dos avanços nas janelas de contexto. 
16  KAG (Knowledge-Augmented Generation / Geração Aumentada por 
Conhecimento): 
 -> O KAG é uma abordagem que combina LLMs (modelos de linguagem 
grandes) com grafos de conhecimento para melhorar respostas que 
exigem raciocínio lógico e conhecimento específico de um domínio. 
 Diferente do RAG, que busca informações em documentos e textos, o 
KAG utiliza informações estruturadas em grafos de conhecimento, 
mostrando relações entre conceitos e permitindo que o modelo 
compreenda melhor as conexões entre eles. 
•  Como funciona: 
 * O conhecimento é organizado em um grafo, onde existem: 
    * Entidades/conceitos (ex.: vinho, carne, tanino); 
    * Relações entre eles (ex.: “Cabernet possui taninos altos” e “taninos 
combinam com carnes gordurosas”). 
* O LLM usa essas conexões para realizar inferências e gerar respostas 
mais precisas. 
• Vantagens do KAG: 
* Raciocínio lógico aprimorado: os grafos permitem que o modelo faça 
conexões e inferências mais complexas. 
* Respostas mais precisas: como o conhecimento está estruturado, reduz 
ambiguidades e melhora a relevância das respostas. 
* Uso em áreas especializadas: é útil em domínios que exigem alta 
precisão, como medicina, direito e finanças. 
• Desafios do KAG: 
=====PAGE=====
* Maior complexidade de implementação: criar, integrar e manter grafos 
de conhecimento exige mais engenharia. 
* Dependência de dados estruturados: a qualidade das respostas 
depende da existência e da qualidade do grafo de conhecimento. 
17 GraphRag x KAG:  
• GraphRAG (Graph Retrieval-Augmented Generation) 
 -> O GraphRAG é uma evolução do RAG tradicional que adiciona grafos de 
conhecimento ao processo de recuperação de informações. 
* Constrói o próprio grafo a partir de textos. 
* Extrai entidades e relacionamentos de um conjunto de documentos. 
* É útil para analisar dados complexos e encontrar temas e conceitos 
dentro de dados privados ou específicos.  
Fluxo: 
     Texto bruto →   Criação do grafo →     Recuperação de informações 
→          Resposta da LLM 
• KAG (Knowledge-Augmented Generation)  
* Utiliza grafos de conhecimento já existentes. 
* Esses grafos normalmente são especializados em algum domínio 
específico. 
* Fornece um contexto estruturado para a LLM, permitindo respostas mais 
precisas e inferências mais complexas. 
Fluxo:  
Grafo de conhecimento pronto → Recuperação do conhecimento → 
Resposta da LLM. 
• Diferença entre GraphRAG e KAG 
Apesar de ambos utilizarem grafos de conhecimento para melhorar 
respostas, a principal diferença está na origem desse conhecimento.

19 SELF RECLETIVE RAG: 
• Self-RAG (Self-Reflective Retrieval-Augmented Generation) 
-> O Self-RAG (Geração Aumentada por Recuperação Autorreflexiva) é 
uma evolução do RAG tradicional que combina LLMs, recuperação de 
informações e autorreflexão. 
-> A principal diferença é que o RAG tradicional sempre recupera uma 
quantidade fixa de informações antes de responder, enquanto o Self-RAG 
decide de forma adaptativa quando precisa buscar informações, quantas 
vezes deve buscar e se a busca é realmente necessária. Além disso, ele 
avalia a própria resposta antes de finalizá-la. 
•  Principais características: 
 1. Recuperação Adaptativa 
* O modelo decide se precisa consultar informações externas. 
* Pode fazer uma ou várias recuperações durante a geração da resposta. 
* Também pode não realizar busca quando considera que já possui 
conhecimento suficiente. 
 
2. Autorreflexão  
* O modelo utiliza tokens de reflexão especiais para analisar suas próprias 
respostas. 
* Ele verifica se a resposta está correta, relevante e baseada nas 
informações recuperadas. 
* Isso ajuda a reduzir erros e informações falsas. 
 
3. Controle durante a Inferência 
* Os tokens de reflexão permitem maior controle sobre o comportamento 
do modelo durante a geração. 
=====PAGE=====
* O modelo consegue ajustar sua resposta conforme a necessidade da 
tarefa. 
• Vantagens do Self-RAG: 
    Maior precisão factual 
 * A avaliação da própria resposta reduz informações incorretas ou 
desatualizadas.  
   Mais flexibilidade e versatilidade 
* O modelo escolhe quando buscar informações e quando revisar sua 
resposta, adaptando-se melhor a diferentes tarefas. 
   Melhoria contínua 
 * A autorreflexão permite que o modelo avalie suas gerações e melhore a 
qualidade das respostas. 
20 – ADAPTIVE RAG: 
• Adaptive RAG (RAG Adaptativo) 
 -> O Adaptive RAG é uma evolução do RAG tradicional que permite ao 
sistema escolher dinamicamente a melhor estratégia de recuperação de 
informações conforme a complexidade da pergunta. 
Enquanto o RAG tradicional usa sempre a mesma forma de busca, o 
Adaptive RAG analisa cada consulta e decide se precisa ou não recuperar 
informações externas, e quantas vezes deve fazer isso.  
• Como funciona: 
 1. Classificação da complexidade da consulta  
* Um classificador avalia a pergunta e identifica se ela é simples, 
moderada ou complexa. 
2. Escolha dinâmica da estratégia 
    Dependendo da complexidade, o sistema escolhe: 
− Sem recuperação: 
=====PAGE=====
    Para perguntas simples, o LLM responde usando apenas seu 
conhecimento interno. 
− Recuperação única: 
    Para perguntas moderadas, realiza uma busca externa uma vez para 
complementar a resposta. 
−  Recuperação iterativa: 
    Para perguntas complexas, faz várias buscas e combina informações de 
diferentes fontes até conseguir uma resposta mais completa. 
• Vantagens:  
* Maior eficiência: evita gastar processamento fazendo buscas 
desnecessárias em perguntas simples. 
* Maior precisão: usa mais etapas de recuperação quando a pergunta 
exige mais conhecimento. 
* Flexibilidade: consegue lidar com perguntas de diferentes níveis de 
dificuldade. 
21 – Corrective RAG (CRAG):  
-> O CRAG é uma evolução do RAG tradicional que adiciona avaliação e 
correção da recuperação de informações antes da geração da resposta. 
Ele verifica se os documentos encontrados são realmente relevantes e 
confiáveis, evitando respostas baseadas em informações incorretas. 
• Como funciona: 
* Um avaliador analisa os documentos recuperados e gera um nível de 
confiança. 
* Alta confiança: usa os documentos encontrados para gerar a resposta. 
* Baixa confiança: faz uma nova busca (como na web) para encontrar 
informações melhores. 
* Confiança ambígua: combina refinamento dos documentos com novas 
buscas. 
=====PAGE=====
-> Além disso, realiza refinamento do conhecimento, separando os 
documentos em fragmentos relevantes e removendo informações 
desnecessárias ou repetidas. 
• Vantagens:  
   Maior precisão e redução de respostas erradas. 
   Recuperação mais flexível com novas buscas quando necessário. 
   Pode ser integrado a outros sistemas RAG para melhorar a qualidade 
das respostas. 
• Em resumo: 
CRAG avalia a qualidade dos documentos recuperados, corrige a busca 
quando necessário e só então gera a resposta.

=====PAGE=====

autenticação, autorização, criptografia e atendimento a normas 
como LGPD, GDPR e HIPAA.

passa por um modelo mais forte, que relê pergunta e documento juntos, e 
reordena pela relevância real.

21 Automação de Pipelines RAG:

02 - O que é Sistema de Recomendação 
=====PAGE=====
-> Um Sistema de Recomendação é um conjunto de técnicas e 
algoritmos que analisa dados dos usuários e dos itens para sugerir 
conteúdos relevantes com base em preferências, comportamento e 
histórico. É muito usado em streaming, e-commerce, redes sociais e 
outras plataformas. 
Principais abordagens: 
• Filtragem Colaborativa: recomenda itens com base no 
comportamento de usuários com gostos semelhantes. 
• Filtragem Baseada em Conteúdo: recomenda itens parecidos com 
os que o usuário já gostou, analisando suas características. 
• Métodos Híbridos: combinam as duas abordagens para aumentar a 
precisão. 
Atualmente, esses sistemas utilizam IA, aprendizado de máquina, redes 
neurais, aprendizado profundo (Deep Learning) e aprendizado por 
reforço para gerar recomendações mais personalizadas e contextuais. 
04 - Uso de SQL Para Recuperação Eficiente de Dados Estruturados: 
 -> Linguagem SQL é usada para recuperar dados de forma eficiente em 
bancos de dados estruturados, permitindo consultas otimizadas para 
grandes volumes de informações. A eficiência da recuperação depende de 
diversos fatores, como a estrutura da consulta, o design do banco e o uso 
correto de índices. 
Algumas práticas são fundamentais: 
• Seleção de Colunas Específicas; 
• Uso de Índices; 
• Filtragem com WHERE; 
• JOINs Eficientes; 
• Agrupamento e Ordenação Otimizada – O uso de GROUP BY e 
ORDER BY deve ser feito com moderação, pois pode exigir 
ordenação e processamento adicional.  
=====PAGE=====
• Uso de Views e Materialized Views – Permitem otimizar consultas 
complexas préprocessando os dados. 
•  Particionamento de Tabelas – Em bancos de grande escala, dividir 
os dados em partições pode melhorar a recuperação. 
05 - Métricas e Avaliação de Desempenho em Recomendações 
Personalizadas: 
-> A avaliação de um Sistema de Recomendação mede a qualidade das 
recomendações e ajuda a melhorar o modelo. As métricas variam 
conforme o objetivo do sistema. 
1. Métricas de Precisão 
• RMSE e MAE: medem o erro entre as previsões do sistema e as 
avaliações reais dos usuários. 
• Precision: mede quantos itens recomendados são realmente 
relevantes (Top-K). 
• Recall: mede quantos itens relevantes o sistema conseguiu 
recomendar (Top-K). 
2. Métricas de Ranqueamento 
• NDCG: avalia se os itens mais relevantes aparecem nas primeiras 
posições da lista. 
• MRR: mede a posição do primeiro item relevante, favorecendo listas 
em que ele aparece logo no início. 
3. Métricas de Cobertura e Diversidade 
• Cobertura: mede quanto do catálogo foi recomendado. 
• Diversidade: verifica a variedade dos itens recomendados. 
• Serendipidade: mede a capacidade de recomendar itens 
inesperados, mas relevantes. 
=====PAGE=====
4. Métricas de Engajamento 
• CTR (Click Through Rate): porcentagem de recomendações 
clicadas. 
• Tempo de retenção: quanto tempo o usuário interage com os itens 
recomendados. 
• Conversão: verifica se o usuário realizou a ação desejada (compra, 
play, leitura etc.). 
--> A métrica ideal depende do objetivo do sistema. Por exemplo, sistemas 
de vendas priorizam CTR e conversão, enquanto sistemas educacionais 
podem priorizar diversidade e retenção. O uso de várias métricas 
fornece uma avaliação mais completa do desempenho.

-> Não precisa colocar todos os dados no RAG, pois ele enviou somente as

baseia no cosseno do ângulo entre esses dois vetores, sendo 
particularmente útil

    1: vetores têm a mesma direção (ângulo 0°), são muito semelhantes.

4 – Infraestrutura para implementar RAG: 
-> Para funcionar na prática, o RAG não depende apenas de um LLM. Ele 
precisa de uma infraestrutura com diferentes componentes: um banco de 
dados vetorial para armazenar informações, modelos de embeddings 
para transformar dados em representações numéricas e permitir buscas 
por significado, um orquestrador para conectar todos os componentes e 
um LLM para gerar as respostas. 
Essa arquitetura pode ser dividida em microserviços, onde cada parte 
executa uma função específica, como busca de documentos, 
processamento da linguagem e geração de texto. Serviços em nuvem, 
como a AWS e Azure, oferecem ferramentas que ajudam a montar esse 
fluxo, conectando busca e modelos de IA por meio de APIs. 
Assim, o RAG adiciona uma camada de busca e conhecimento externo ao 
LLM, permitindo que ele consulte informações atualizadas e relevantes 
em tempo real, gerando respostas mais precisas do que um LLM usado 
sozinho.

Mód 13 – Parte II: 
15 – Motor de consultas:  
-> O dsa_queryengine.py implementa o motor de consultas de um sistema 
GraphRAG, que combina busca vetorial com um grafo de conhecimento 
para responder perguntas. 
=====PAGE=====
o  QueryEngine é a classe principal. Quando o usuário faz uma 
pergunta, ela primeiro realiza uma busca vetorial (em um índice 
como FAISS ou ChromaDB) para encontrar os documentos mais 
relevantes e formar um contexto inicial. 
o AnswerCheck verifica se esse contexto já contém informações 
suficientes para responder completamente à pergunta. 
o  Se o contexto for suficiente, a resposta é gerada imediatamente. 
o Se não for suficiente, o QueryEngine expande o contexto navegando 
pelo grafo de conhecimento, buscando nós relacionados. 
o Essa expansão usa uma fila de prioridade (heapq), para visitar 
primeiro os nós com maior similaridade semântica com a pergunta. 
o A cada nova informação encontrada, o AnswerCheck verifica 
novamente se já é possível responder. 
o Se, mesmo após a expansão, não houver uma resposta completa, o 
modelo de linguagem (LLM) gera a melhor resposta possível usando 
todo o contexto acumulado. 
 -> O sistema começa com uma busca por embeddings (vetorial), verifica 
se já consegue responder e, se necessário, explora o grafo de 
conhecimento para enriquecer o contexto antes de gerar a resposta final. 
 
 
 
 
Mód 15 – Agentic RAG e LLM routing com LangGraph: 
02 - Roteamento Inteligente: 
-> Roteamento Inteligente é o uso de regras, dados ou IA para decidir 
automaticamente o melhor destino para uma tarefa, analisando a 
solicitação e os recursos disponíveis. 
 -> Diferente do roteamento simples (regras fixas), ele escolhe 
dinamicamente o melhor modelo, agente ou recurso, melhorando custo, 
velocidade, qualidade e eficiência do sistema. 
=====PAGE=====
03 – LLM Routing: 
-> LLM Routing é uma técnica de roteamento inteligente que direciona 
cada solicitação para o LLM, agente ou ferramenta mais adequado para 
aquela tarefa. 
 Ele funciona como um despachante inteligente: analisa o prompt, decide 
o melhor recurso e encaminha a solicitação.  
• Benefícios: 
o  Maior qualidade: usa o modelo especializado para cada tarefa. 
o Menor custo: tarefas simples vão para modelos mais baratos. 
o Maior velocidade: escolhe modelos mais rápidos quando possível. 
o Mais capacidades: direciona para agentes ou ferramentas com 
recursos específicos. 
o  Mais modularidade: combina vários LLMs e ferramentas em um 
sistema mais eficiente. 
•  Funcionamento: 
 1. Analisa a solicitação. 
2. Escolhe o LLM, agente ou ferramenta ideal. 
3. Encaminha o prompt. 
4. Retorna a resposta ao usuário. 
❖  LLM Routing x Routeamento inteligente:  
  
-> O LLM Routing é um tipo específico de roteamento inteligente aplicado 
a modelos de linguagem.  
Enquanto o roteamento inteligente decide dinamicamente para onde 
enviar uma tarefa (LLM, agente, ferramenta ou recurso), o LLM Routing

02 – IA Generativa multimodal:  
-> IA Generativa Multimodal é um tipo de Inteligência Artificial capaz de 
processar, compreender e gerar conteúdos usando diferentes tipos de 
dados (modalidades) ao mesmo tempo, como texto, imagens, áudio, 
vídeos e código. 
-> A IA Generativa Multimodal é uma IA capaz de “ver”, “ouvir” e “ler”, 
combinando diferentes tipos de informações para criar conteúdos novos 
e variados. 
Diferente de uma IA limitada a apenas uma modalidade (ex.: somente 
texto ou somente imagem), ela consegue: 
• Receber entradas de diferentes formatos (ex.: uma imagem junto 
com uma pergunta em texto). 
• Entender a relação entre essas modalidades (ex.: interpretar uma 
imagem e relacioná-la com uma descrição escrita). 
• Gerar novos conteúdos, podendo ser: 
=====PAGE=====
o De uma única modalidade (ex.: criar um texto a partir de uma 
imagem). 
o De múltiplas modalidades (ex.: criar um vídeo com narração a 
partir de um roteiro em texto).
